Presentation rules supported by this evidence:

- m.Int32(7) initially carries a Python payload; capture/IR consumption emits
  arith.constant. The constructor does not eagerly emit the constant.
- A staged Int32 + Int64 promotes to Int64 via arith.extsi and arith.addi.
- x.to(m.Int64) and m.Int64(x) both use the numeric conversion mechanism.
- Staged Int64 -> Int32 narrows via arith.trunci; no runtime range check is
  implied. Source review shows out-of-range Python literal casts can warn.
- Int32 -> Float32 emits arith.sitofp; Float32 -> Int32 emits arith.fptosi.
- Mixed signedness is supported and is not a suitable error example.
- Different unsupported FP8 formats require an explicit common dtype.
- x.to(int) rejects runtime SSA values with PHASE_REQUIRES_CONSTANT.
- Scalar promotion rules are not a blanket promise for vectors/custom leaves.
