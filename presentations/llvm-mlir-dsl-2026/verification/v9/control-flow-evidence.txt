Recommended slide claim
-----------------------
Different IRs expose different loop terminators. That changes frontend
capture and region construction as well as the final compiler pipeline.
Do NOT say that the whole SCF dialect cannot represent early termination.
The comparison should specifically name scf.for versus cuda_tile.loop.

Official NVIDIA evidence
------------------------
Current operations reference, retrieved 2026-10-06:
https://docs.nvidia.com/cuda/tile-ir/latest/sections/operations.html
Sections 9.5.2 break, 9.5.3 continue, 9.5.4 for, 9.5.6 loop, 9.5.7 return.

Short quote (4 words): "innermost enclosing loop operation".

Summary: cuda_tile.loop exits through break; a break in a nested if can
transfer directly out of that loop. continue targets the nearest enclosing
loop, including for/loop, rather than yielding only from the nested if.
This is not a labelled escape to an arbitrary outer loop. cuda_tile.for is
range-based, must finish each path with continue, and cannot terminate early.
The current latest loop also permits return from the enclosing function;
return is still excluded from for. Entry kernels have no return operands.
Do not show break terminating cuda_tile.for.

Pinned 13.1 operations reference:
https://docs.nvidia.com/cuda/tile-ir/13.1/sections/operations.html
Sections 8.5.2 break, 8.5.6 loop, 8.5.7 return.

Short quote (9 words): "Early returns from inside loops are not supported".

The pinned release supports loop+break and nested-if break, but requires
leaving the loop before returning from the function. Therefore keep the
tutorial's comparison on break rather than general early return unless the
target version is explicitly specified. The earlier v8 Tile examples used
13.1 references; do not silently import newer return semantics into them.

Official MLIR evidence
---------------------
https://mlir.llvm.org/docs/Dialects/SCFDialect/
Sections scf.for, scf.if, scf.yield, scf.while, scf.condition, scf.execute_region.

Short quote (8 words): "exactly one block that terminates with scf.yield".

Summary: scf.for has a fixed range and a single-block body with scf.yield.
scf.if regions likewise yield to their parent operation. There is no direct
SCF break terminator jumping from that nested if out of scf.for. However,
scf.while makes continuation data-dependent through scf.condition; false
ends the loop. Frontends can transform a source break into this form.
scf.execute_region also admits a multi-block CFG inside a region and returns
results through its exits. It does not itself mean an arbitrary nonlocal
escape from an enclosing for. SCF supports nested control flow, so do not
repeat the NVIDIA prose as if nesting were unique to Tile IR.

Current frontend implementation is a separate question
------------------------------------------------------

plugins/ast_preprocessor/preprocessor.py:

  1051–1065: an if/while owning an exit can remain native Python; Meta
             predicates execute normally, staged predicates are rejected.
  1950–1965: transform_for_loop rejects early exits on its staged path.
plugins/ast_preprocessor/helpers.py:
  467–497: early_exit_predicate accepts Meta bools and diagnoses staged ones.
plugins/dialects/scf/executors.py:
  410: range executor builds SCF for.
  561: while executor builds SCF while.

Thus a diagram about dialect capabilities is not evidence that the current
reference Python frontend accepts arbitrary staged Python break/return.
Meta Python exits remain valid. Supporting richer staged exits may require
a custom AST preprocessor, not only substituting its region callbacks:
the shared rewrite can reject an exit before the emitter is reached.
ASTPreprocessorPlugin.preprocessor_class is the seam for that choice;
executors(dsl) supplies the associated callbacks. See core/plugin.py:131
and core/dsl.py:655–688. DialectPlugin selects matching operations,
providers and lowering, not a universal Python control-flow policy.

Suggested layout, not extra prose: two nested-region diagrams. SCF's inner
yield returns to its containing operation. Tile's inner break arrow leaves
the surrounding loop. Put the SCF while/condition caveat below the SCF panel
so the comparison remains precise. Show these as IR capabilities; presenter
notes state the current AST restrictions separately.

Avoid on slides
---------------

- break attached to cuda_tile.for.
- Unversioned claims about all Tile loop returns.
- Claiming the DKG native frontend already captures every legal Tile exit.
- Claiming one executor override bypasses all existing AST restrictions.
