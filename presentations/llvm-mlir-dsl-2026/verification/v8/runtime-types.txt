Required v7 slide corrections
-----------------------------
All program examples: import mlir.mlir_dsl as m. mlir.dsl is the core authoring
namespace; it exports types/BaseDSL/protocols, but no jit/kernel/compile.

15: Keep the six conversion rows for the LLVM reference sub-DSL, but insert
    OpEmitter between dtype/promotion and operations. NumericMeta.mlir_type
    asks the active emitter; scalar_mlir_type is the builtin scalar behind
    the dtype. Other dialects can use rank-0 tiles for the same m.Int32.
16: Pointer and Vector use emitter hooks too. @m.struct is now a frozen
    field-by-field pytree, NOT a single LLVM struct SSA value. No packed or
    zero_init options. The LLVM host-entry helper may pack several returned
    fields into an LLVM struct for its ABI; that is separate from @m.struct.
    Torch dtype conversion is in plugins/thirdparty/pytorch/dtypes.py.
    Math operation helpers belong to the LLVM dialect plugin.
17: Local numeric inference remains valid. An unannotated Python scalar or
    Python-typed scalar is Meta. Do not generalize this to every unannotated
    object: DSL leaves and framework objects with adapters can stage without
    annotations. Constexpr no longer exists or needs to be written.
18: Replace the custom MyNumber/future-hook story with the real OpEmitter
    protocol and DialectPlugin.emitter. The core Numeric/Vector/Pointer
    classes can retain their surface while another emitter changes SSA types
    and operations. Hooks are demonstrated by test/plugins_dialect.py.
19: register_leaf still packages ir_types/ir_values/from_ir_values; optionally
    marshal for a host ABI, reference for memory-like leaves. The existing
    three-callback code remains a staged-only custom Tensor sketch.
22: Replace m.Array with m.Pointer[m.Float32], and ops: m.Constexpr with ops.
    If using multiple blocks, compute block_idx * block_dim + thread_idx;
    carry n: m.Int32 and guard i < n. GpuPlugin owns these helpers, gpu.func
    and .launch(grid=..., block=...) from the host @jit entry.
23: DLPack is implemented, not merely an extraction target. Show:
    tensor -> DlpackTensor metadata/lease -> contiguous Pointer[T] -> LLVM ABI.
    Shape/strides are inspected on the host; the pointer ABI does not carry
    them automatically. Pass n (or other required dimensions) separately.
    No m.Array exists. PyTorch has its own lazy type adapter; the generic
    DLPack protocol adapter is a separate optional plugin.
24: Show m.compile(func, *representative_args) -> compiled(*matching_args).
    compile[...] / GenerateLineInfo / export_to_c / to_precompiled_mlir are
    absent from this implementation. Do not present those DkgDSL APIs as
    current mlir dsl APIs. KEEP_IR and DRYRUN can inspect generated IR; they
    are not a portable object/C-artifact AOT export API.
25: Plugin owns the host-entry helper. LLVM reference emits func.func with
    llvm.emit_c_interface and lowers via convert-func-to-llvm. Remove the
    prior host_entry='llvm'/'func' selector claim. TVM-FFI export is implemented
    via TvmFfiPlugin and compiled.tvm_ffi_function, enabled by
    MLIR_DSL_ENABLE_TVM_FFI=1. Plain TVM-FFI calls receive DataPointer addresses;
    compiled(...) applies the normal Python buffer adapters first.
26: Frontend DSLUserCodeError and compiler remarks remain separate. Remarks
    session spans trace and passes. collected_remarks is the last compile's
    list; REMARKS_OUTPUT streams instead of collecting/rendering. Preserve
    the current diagnostic-example failure below; do not claim all examples
    or the whole diagnostic suite passed.
27: Existing tooling settings remain valid; update source paths to the new
    tree. DEBUGINFO, LOC_TRACEBACKS, VERIFY_TRACE, REMARKS[_OUTPUT], PRINT_IR,
    KEEP_IR and PROFILE_COMPILER are available.
28: Memory cache stores a callable/engine; disk cache stores lowered MLIR
    bytecode + CRC32, skipping passes on a hit but rebuilding the engine.
    Calls still trace to identify the module. Hash inputs include bytecode,
    compile-affecting environment, pipeline, extra library paths, toolchain
    binary identity. Current binary identity is path/size/mtime_ns, not a
    guaranteed compiler version string or canonical IR hash.

import mlir.mlir_dsl as m

@m.jit
def affine(x: m.Int32, factor):
    return x * factor + 1

compiled = m.compile(affine, 4, 3)
result = compiled(5, 3)  # 16; factor remains the specialized Meta value.

@m.jit
def scale(p: m.Pointer[m.Float32], n: m.Int32):
    for i in range(n):
        p[i] = p[i] * 2.0

# A contiguous framework buffer with a registered adapter can be passed to p.
# n is a separate runtime scalar; no m.Array or wrapper annotation is needed.

Limits
------
No JAX, CUDA device execution, custom real Tile IR emitter, C artifact export,
bitstream/YAML remark streaming, or entire lit suite was tested. DLPack
metadata supports more framework producers than were exercised here; runtime
adaptation requires supported dtype/device and contiguous storage. Framework
memory ownership remains with the producer/caller. A custom dialect that
provides an emitter replaces the default dialect set and must supply the
entry/compiler/lowering hooks its execution path needs. Passing the stand-in
emitter test does not supply those hooks for a real target automatically.
