SLIDE 08 — MLIR compilers make different choices
Owner: Guray Ozen
Clock: 05:00–05:15
Target duration: 00:15

After the use cases and the choice of Python as a metaprogram, explain why MLIR needs a composable DSL architecture. MLIR serves many dialects, pass pipelines and frontend capture rules; one fixed frontend/lowering choice cannot cover all of them. This is the motivation for a shared core with selected plugins. Keep this slide as three short spoken prompts, not a compiler or region diagram. Compiler A and B may use unrelated dialects and lowering pipelines; their Python frontends can also require different capture rules. The shared DSL infrastructure therefore needs replaceable target-specific behavior. Ask how one core can support those choices, then define the plugin concept before drawing the solution. If a concrete control-flow example helps, use the source-checked comparison below verbally.

Optional presenter example retained from v9: Use a precise IR comparison, not the blanket claim that SCF cannot express early termination. CUDA Tile IR loop has a break terminator that may occur in a nested if and targets its enclosing loop. SCF for is a counted, single-block region ending in scf.yield, without a direct break terminator. SCF while can terminate via scf.condition; a frontend can lower Python break using a different representation or rewrite. Therefore identical Python surface syntax may need a different AST strategy, callback set, region construction and lowering per target. The picture compares IR capabilities, not a claim that the current DKG Tile frontend already captures every early exit. Do not conflate loop break with early function return: Tile rules differ by operation/version. Sources are recorded in the accompanying evidence file. CUDA Tile for also disallows early termination: the left picture deliberately uses loop, not for. A custom ASTPreprocessorPlugin may need to replace preprocessor_class itself because the current shared rewrite can reject staged exits before callbacks run; changing only the loop executor does not guarantee support.
